# Failure modes

| Failure | Effect | Handling |
|---|---|---|
| Daemon not running | A bare cargo warns and uses its own pool, as today | The pool goes with its daemon once nobody holds it: a semaphore by itself, a FIFO through the daemon's warden ([host pool](host-pool.md), Lifetime). `cargo heli` or `cargo heli ensure` starts the daemon; logon task or session hook |
| Daemon and its warden both gone (Unix: a kill of both, a power loss) | The FIFO stays, with no bytes: a bare cargo runs one job at a time, without a warning | The next daemon fills it again ([host pool](host-pool.md)); `cargo heli ensure` as a session-start hook, or the logon task, starts one early |
| Daemon unreachable, silent for 5 s, of another protocol version, or older and without a request the client sends | `cargo heli` cannot hand over the run, or the request | The command runs directly (`log` reads the record itself) after one warning line; a newer client asks an older daemon to exit once idle ([daemon](daemon.md)) |
| Daemon lost while a run waits (worktree lock, recycling) | The command never started | The client runs it directly, after one warning ([daemon](daemon.md)) |
| Daemon lost once a run's command started | The client cannot tell whether the command finished | The client exits 1 and does not run the command again |
| A client is killed, or stops reading, during a run | none | The run goes on and its record is complete; `status` lists it as done if no client heard its end; the same command attaches to it while it runs ([runs](runs.md)) |
| Two daemons on one state directory (Windows logon sessions) | They could give the same run id, and write one record over another | Ids come from the state directory's counter under a lock, above every record ([runs](runs.md)) |
| An agent harness stops the command that started the daemon | Observed (Claude Code, Windows): it kills the command's process tree, found through parent processes | The daemon is started through a short-lived intermediate, so it descends from no client ([daemon](daemon.md)) |
| An agent harness terminates its whole job object | On Windows, a daemon started on demand inside a job that refuses breakaway (Claude Code's) dies with it, and every run with it | Not seen in normal operation: that job holds the whole app and has no kill-on-close limit. Once `setup --autostart` registered the logon task, the daemon starts outside any agent's job: at logon, and when a client needs one, through `schtasks /Run` ([daemon](daemon.md)) |
| Daemon started outside the user's interactive session (a service, or a task that runs while the user is logged off) | Runs lose the desktop: tests that drive real windows fail | The daemon runs only in the interactive session: started by a client, or by a logon registration restricted to the logged-on user (`InteractiveToken`, a systemd user unit, a launchd agent in the Aqua session; [host pool](host-pool.md), "Autostart"). `status` shows the daemon's session, and on Windows its window station and desktop and whether they are interactive ([observability](observability.md)) |
| The logon registration is gone or stale (removed by hand, heli installed elsewhere, other locations) | A start through it would bring up no daemon, or the wrong one | A client uses it only when the record names its own program and locations; when the service manager refuses the start, the client starts the daemon itself ([daemon](daemon.md)) |
| Daemon crashes mid-build | Running cargos keep their handles: a Windows semaphore lives while any handle is open, and a FIFO keeps its bytes while any process holds it open (its path persists either way) | The restarted daemon adopts a pool still held, as it is; a FIFO that nobody held has lost its bytes, and the daemon fills it again ([host pool](host-pool.md)) |
| Slot leak by bare cargo | The host pool shrinks | Top-up at quiescence, bounded by the target ([host pool](host-pool.md)) |
| Run killed while holding slots | none | The run pool's loans go back in full ([host pool](host-pool.md)) |
| The pool holds more than the target (a FIFO has no maximum; a semaphore's is N, above the target while slots are withheld) | Oversubscription | The daemon drains the surplus at once ([host pool](host-pool.md)) |
| Memory spike | New jobs wait | Slots are withheld; running jobs finish |
| GC races a build | none | Try-lock, rename to trash, skip busy directories |
| `gc` or the daemon stopped while deleting the trash | What is left there takes disk | It counts as free for the floor and in no directory's size; the daemon's deleter, at start and every minute, or the next `gc`, deletes it |
| Recycled unit with a donor path compiled in | Tests read the removed worktree | The rustc dep-info scan invalidates the unit ([recycling](build-store.md#recycling)) |
| Recycled directory with a stale record | Could link stale code | A record counts only if it is newer than every file in the build directory; otherwise conservative mode |
| Recycling into a worktree made before the donor's last build (the main worktree's first run, the look) | Its unchanged-looking files are older than the donor's artifacts: cargo would link the donor's code | Precise mode gives every file not of the recorded content a time after that build; conservative mode does not recycle into such a worktree ([recycling](build-store.md#recycling)) |
| A recycler taking a directory another one has just renamed into place | One worktree's build directory moved to another | The donor's manifest names the new workspace before the rename: a claimed donor is no orphan ([recycling](build-store.md#recycling), "The claim") |
| Tools looking in `target/<profile>/deps` | They miss moved intermediates | Validated on a real workspace before phase 2 ([placement](build-store.md#placement)) |
| False green from the cache | A flaky pass is reused | Printed caveat; `--no-cache` |
| heli runs itself in a loop | Unbounded processes | `heli` is refused as a subcommand; `HELI_DEPTH` stops at 16 |
| Another logon session (SSH, a service) | On Windows, a separate session namespace, so a separate pool, and a separate daemon (its endpoint and lock carry the session id) | Documented; a global namespace needs admin rights (later) |
